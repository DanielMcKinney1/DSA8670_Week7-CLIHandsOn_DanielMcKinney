# Reflection: where Codex struggled, what surprised you, how your prompts had to evolve, and one thing you would do differently if you ran the task again.





The part where codex struggles is it requires extremely precise instructions on what to do, but also what not to do. I initially thought I had covered all my bases regarding a fully descriptive prompt that would provide context without prompting action, but codex still ran with it and produced an output that I had not intended. It is exceptionally quick at producing a file which accomplishes my intention, but slow at actually getting the intention within the intended parameters, which I suppose is user error.  



The main aspect that surprised me with codex was the speed at which is produces working code. When I have use chat-gpt to produce or review code for various projects, it always seems to mess something up in a major way that makes the code either not work as intended or not work at all. What was surprising with codex is that it was able to, on the first try, produce something that fulfilled the purpose as I described. I believe this is partially because it can fully read the dataset being analyzed as well as the entire code file, instead of with chat-gpt where I had to explain verbally the dataset and the code file and have it try to produce code that fits within that verbal description. Regardless of why, it was surprising how little of a headache it was to get it to produce almost exactly what I wanted. 



Where my prompts had to evolve was being incredibly specific with what I wanted it to do. Because I am used to using ai in the capacity to alter code I have already written, I did not need to include as much context or intention because I always needed to complete a relatively small chunk of code at one time and I had always given it a basis to start from. With codex in this application, it generates the entire file, so I cannot simply write most of the code and tell it to fix it, instead I must completely and precisely explain where everything is, what everything is, where everything must go, and how it should be completed. Additionally, because codex is much less 'chatty' than chatgpt, I felt that I could not use as many small prompts to explain context, and instead felt that it would be better to put all the context and instructions in a singular, comprehensive prompt.



One thing I would do differently if I ran the task again is to try and include more precise instructions on when to make edits, because it created files on a prompt I had intended to be solely for providing context and information, and not a call to action for creating the python files. Additionally, I might try to include instructions to install relevant packages for the project, as the python environment it was using did not have access to the packages it needed, so I had to manually install the packages and run the python files myself when I could have optimized out that step in my initial prompt.
